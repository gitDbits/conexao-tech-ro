» Por que SDD com IA? «

O que a IA faz sozinha, e o que a spec resolve

ANTES

  • Prompt vago: a IA adivinha o requisito
  • A IA constrói o que você descreve; se for vago, o erro vem em grande escala
  • Tarefa grande estoura o contexto do agente
  • Vários agentes mexendo nos mesmos arquivos
  • Documento que envelhece longe do código

DEPOIS

  • Spec declara comportamento, restrições e erros
  • Critérios claros que dá para conferir
  • Plan e tasks quebram em partes que cabem nele
  • Tarefas em partes que não se sobrepõem
  • Spec fica no repositório, junto do código

A IA não adivinha melhor. Ela erra menos quando não precisa adivinhar.

» O que é SDD? «

Spec-Driven Development, ou Desenvolvimento Guiado por Especificação

SDD é uma metodologia em que escrevemos primeiro a spec, um documento que descreve o que será construído, e só depois a IA programa seguindo esse documento.

COMO É EXECUTADA 5 passos, cada um gera um arquivo

PASSO 1ESPECIFICAR/sdd:specifygera spec.mdDescreve o que será feito e por quê, com critérios para conferir
PASSO 2PLANEJAR/sdd:plangera plan.mdDefine como fazer: decisões técnicas e regras do projeto
PASSO 3TAREFAS/sdd:tasksgera tasks.mdDivide o trabalho em passos pequenos, com o teste antes do código
PASSO 4IMPLEMENTAR/sdd:implementgera códigoExecuta as tarefas, uma de cada vez
PASSO 5VALIDAR/sdd:validategera relatórioConfere se o código cumpre o que a spec prometeu

OPCIONAIS clarify • spec-review • checklist • analyze

BUG PEQUENO /sdd-change: specify, tasks e implement

» Por que PR padrão com IA? «

O que acontece com PR solto, e o que o padrão resolve

ANTES

  • Título vago, do tipo “ajustes”
  • Descrição de uma linha, sem contexto
  • O revisor não sabe como validar
  • O checklist é esquecido
  • A IA descreve arquivos, não comportamento

DEPOIS

  • tipo(escopo): descrição, até 72 caracteres
  • Contexto: por que a mudança foi necessária
  • Como testar, passo a passo
  • Checklist no corpo: RuboCop, testes, migrações
  • O que foi feito foca no comportamento

A descrição é o contexto do revisor.

Limite: a skill escreve a descrição, mas quem confere se ela é verdadeira é o autor.
